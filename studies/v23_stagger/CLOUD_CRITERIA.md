# v2.3（B）云端全矩阵判定准则（跑前写死，2026-10-23）

scope R3 原文："判据形式先行写死；数值阈值云端全量跑之前写死，
出数后调整一律重新送审"。此前邮件与 LIGHT_RESULTS.md 初版误写成
"云端全量跑之前不写死"，方向相反，特此更正并按下述准则执行。
本准则为云端跑前写死版本；出数后任何阈值/准则调整一律重新送审。

## 1. 收缩定义（scope R1 落实；2026-10-23 管家复核修订）

- 驱动 history.stagger_dT 为标量：每区间只存末次 pass 差
  （induction3d_tet10.py 第 603 行，dT_stagger 循环内覆盖）。因此此前
  factor_5_over_3=0.0938 是 d5/d3（跨 3→5 两个 pass），不是相邻收缩因子；
  d4 在原 {1,2,3,5} 矩阵下任何运行都拿不到。
- 修法（已写死）：云端矩阵 iter 档加 4（仅 tol=None 档），判据改为
  **相邻档比值** d(k+1)/d(k)，k∈{2,3,4}（d1 无定义）。
- 前提与限制（诚实声明）：相邻档比值是**跨运行**比值，前提是跨运行嵌套
  确定性（同一起点、同档内前 k 个 pass 在不同 iter 上限运行中逐位一致）。
  该前提无法从现有标量记录直接验证；轻算例 iter=2/3 终场 Tmax 差 0.02°C
  说明不同上限运行的终场量本就不同，跨档比值含此漂移，
  判据只取 factor<1 的定性方向，不做精确定量比较。
- factor < 1 → 该区间收缩；factor ≥ 1 或 dT 发散 → 该区间不收缩，
  必须如实记录为"不收缩域"，不得只报收敛域。

## 2. tol 推荐的断言形式（scope R2 落实，数值预注册；2026-10-23 管家复核修订）

推荐某 tol* 必须同时满足（全矩阵逐区间成立）：
(a) **至少一个区间实际提前跳出**（passes < 该组 stagger_iter 上限）；
    tol* 推荐基于 **iter=5 档**判定（passes≤5 只是上限保证，不是收敛证据）；
(b) 终场 Tmax 相对 iter=1（tol=None）变化 |Δ| ≤ 10%
    （预注册界；**依据仅为本算例敏感性线索 −8.34%，不是误差定论**）；
(c) 所有区间收缩（相邻档 factor < 1），无不收缩域。
任一不满足 → 结论为"不建议启用固定 tol"（合法研究结论），
或阈值调整后重新送审。

## 3. 0.1–1K 预注册假设（带验证规则；2026-10-23 管家复核修订）

- 假设：候选 tol* ∈ {0.1 K, 1 K}；依据：轻算例 factor≈0.19，
  外推约 4–5 轮可达 0.1–1 K 量级。
- 矩阵落实：0.1/1.0 只加在 iter=5 档（+2 组，云端矩阵共 19 组）；
  tol 提前跳出只有在上限够大时才有鉴别力。**出数后不得再补档**。
- 验证规则：云端矩阵中若某 tol* 在 iter=5 档下至少一个区间触发提前跳出
  且满足第 2 条 (b)(c)，则按第 2 条推荐；否则假设不成立，
  按"不建议启用"或重新送审处理。

本版不改驱动默认（stagger_iter=1 保持）。任何 iter 默认值变更走单独评审。
